# H3 动作迁移 · RunningHub 改进版

`h3_motion_transfer_improved.json` 是在一份 RunningHub 上的 H3「图 + 视频 → 动作迁移」工作流基础上改的，保持 RunningHub / ComfyUI 的界面格式，可以直接导入。

## 流程

参考图（人物 + 场景）和参考视频（编舞）一起送进 `MiniMaxH3ReferenceToVideo`（Ref2VA）。参考图用 Qwen3-VL 4B 自动描述后拼进提示词，采样使用 Ref2V Turbo LoRA 和 SageAttention。输出两路：成片，以及"参考视频 | 参考图 | 成片"三联对比。

## 改了什么

| 改动 | 原因 |
|---|---|
| 参考视频的原声接到 `ref_video_audios.ref_video_audio_0` | 原版只把原声混进成片，模型生成时听不到音乐；接上后它成为 `<Audio 1>`，动作能跟着节拍走 |
| 提示词改用 `<Picture 1>` / `<Video 1>` / `<Audio 1>` | H3 编码参考素材时用的就是这些标签，写"图片1""视频1"模型不一定能对应上 |
| 删除 80×80 出图链（anima 底模 + 14 个 LoRA + 打包下载） | 和成片没有任何连接，只增加加载时间和显存占用 |
| 删除未连接的 BEN2 抠图节点 | 输出没接到任何地方，白跑一遍 |
| 删除"尾链"（cleanGpu → RIFE → SaveImage） | 它的作用是在成片保存后故意让任务报错。这会让平台记录成失败任务，可能违反平台规则，对出片没有帮助 |
| 清掉节点里保存的个人云端预览地址 | 分享工作流时不带个人存储路径 |

采样参数（euler、beta、8 步）和分辨率都没动。我没有实际运行过，这些参数需要在你的显卡上试。

## 和分镜工作流配合

- **参考图**：用分镜单元的首帧关键帧，也就是成员在场景里的定格画面，可以用定妆照 + 场景图合成。不要直接用白底定妆照，否则成片背景也会是白底。
- **参考视频**：一次只放一段 2–15 秒的编舞参考，「生成秒数」不要超过它的时长。
- **一致性**：一张参考图里人越多，身份越容易串。群舞镜头建议先只做前排 2–4 人。
- **版权**：参考视频如果是别人的 MV，迁移出来的动作仍可能涉及编舞版权，公开发布前要确认授权。
