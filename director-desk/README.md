# 导演工作台 Director Desk

剧本结构时间线驱动的自动剪辑工作台（网页原型）。**不调用任何视频识别大模型**：画面和声音只做像素与波形统计，匹配和编排全部由确定性算法完成，同样的输入永远得到同样的剪辑。

## 运行

无需安装、无需联网、零依赖：直接用 Chrome / Edge 打开 `director-desk/index.html`（双击即可）。

```bash
cd director-desk && npm test   # 核心算法单元测试（Node ≥ 18）
```

## 工作流程

1. **导入 / 编辑剧本时间线**（可选）：导入后执行**线性对位**；不导入则执行**非线性自动编排**。
2. **导入素材**：可以多选或拖入视频。与视频同名的 `.txt / .srt / .json` 会作为该素材的内容描述，例如 AI 生成时用的提示词，并参与文本匹配。
3. **分析素材**：导入后自动开始，逐帧统计画面与声音，切分镜头。
4. 在右侧**参数调节台**拖动滑块，时间轴实时重算（150 条素材时单次求解约 50ms）。
5. 在时间轴上手动精修：拖动排序、拖边修剪、分割、删除、撤销重做。
6. **导出**：FCPXML（达芬奇 / Final Cut）、EDL（Premiere / 通用）、ffmpeg 渲染脚本（直接出 MP4）、剪辑表 CSV。

快捷键：`空格` 播放/暂停 · `S`/`B` 分割 · `Delete` 删除 · `Ctrl+Z / Ctrl+Y` 撤销/重做 · `←/→` 逐帧（加 `Shift` 为 1 秒）· `Ctrl+S` 保存工程 · `Ctrl+滚轮` 缩放时间轴。

## 剧本时间线格式

```
# 片名: 谢小娥 精编版
# 线: A | 影戏线（皮影：妖猴与女娃） | #e0622b
# 线: B | 现实线 | #3a6fd8
# 幕: 建置 | 00:00-03:05
A1 | 妖猴屠船 | 00:00-00:41 | 黑暗中锣响……师傅设问：“一个女娃，要怎样才能变成侠客？”
B1 | 从天而降 | 00:33-00:59 | 深夜，申府……
C1 | 江边闪帧 | 00:38-00:39 | 少女躺在江边，睁开眼 @0.4
# 伏笔: 那把剑 | ○C9 ●B9 ○C10 ●C15
```

- 编号的首字母表示叙事线，数字是段落序号。竖线可以换成空格，时间写成 `mm:ss`、`hh:mm:ss` 或带小数的秒都可以。
- 结尾的 `@0~1` 用来手动指定剧情强度。不写时，按所属的幕和动作关键词（斩、打、格挡……/ 睁眼、吃饭……）自动估计。
- `○` 表示埋伏笔，`●` 表示回收伏笔，诊断面板会检查每条伏笔链是否完整、顺序是否正确。
- 段落时间可以重叠：在同一时刻，**开始得最晚的段落可见**。所以插入镜头会打断外层段落，形成交叉剪辑，外层段落的素材在插入结束后接着播放，源素材保持连续。
- 对话框中的“载入示例格式”是按《谢小娥》结构图整理的完整示例（46 段、3 线、4 幕、12 条伏笔）。

## 算法

### 1. 素材分析（`js/media/analyzer.js`，浏览器端）
| 信号 | 计算方式 | 用途 |
|---|---|---|
| 色相直方图 12 档 + 亮度直方图 8 档 | 64 像素宽缩略帧，逐像素 HSV 统计 | 镜头切分、视觉签名 |
| 亮度、反差、饱和度、冷暖 | 帧统计 | 视觉签名（判断素材属于哪条线） |
| 运动量 | 相邻采样帧亮度差的均值，按采样间隔归一 | 能量 |
| 响度 RMS | 解码为 16kHz 单声道，每 50ms 一帧 | 能量、波形、裁剪避让 |
| 对白概率 | FFT：300–3400Hz 频带能量占比高 + 频谱平坦度低 + 高于底噪，再做中值平滑 | 对白与台词匹配 |

采样帧率按时长自适应（2–8fps），每秒保存一张缩略图用于时间轴显示。

### 2. 镜头切分（`js/core/features.js`）
- **硬切**：相邻帧直方图距离 ≥ 分镜阈值，同时 ≥ 2.2 × 局部中值。用局部中值做自适应，避免高运动画面被误切。
- **渐变**（叠化、淡入淡出）：跨 4 帧的直接距离超过阈值，而每一步变化都很小。
- 短于“最短镜头”的碎片并入较弱的那一侧边界。调阈值时会**即时重切**，不需要重新解码。

### 3. 线性对位（有剧本，`js/core/solver.js`）
1. **展平**剧本，得到每个段落的可见区间。按可见时长把每个段落拆成若干**槽位**。
2. 为“镜头 × 槽位”计算多因子分数（权重都可以在参数台调节）：
   - **文件名编号**：素材名里出现 `A3`、`b-12` 等编号即直接对位；编号不符会扣分。
   - **文本相似度**：用字 + 二元组的 TF-IDF 余弦，比较段落标题和描述与素材的文件名和描述。
   - **线索视觉签名**：已知线索的镜头（来自编号或手动标注）构成色调质心，未知镜头用高斯核算出归属概率。这是**开放集**做法，没有样本的线索保留先验，远离所有已知质心的镜头会归到未知线索。
   - **时长贴合**、**能量 ↔ 剧情强度**、**对白 ↔ 台词**。
   - **素材顺序**：只在文件名普遍带序号时才生效。
3. 用**匈牙利算法**求全局最优指派。每个镜头都有一个“弃用”虚拟列，分数低于**置信阈值**的镜头不会被硬塞进时间轴，对应段落留空并标红。**铺开度**控制优先把素材铺到更多段落，还是叠在同一段落里。
4. 段内按素材顺序成流。素材超长时按比例分配长度并**智能取窗**：强度高的段落偏向运动峰值，强度低的段落偏向居中，同时避免在响度高处（台词中途）下剪。

### 4. 非线性编排（无剧本）
1. **MMR 选片**：综合镜头质量（长度合适、不黑、有反差）和与已选镜头的差异度，去掉重复的生成变体。
2. **束搜索排序**，代价包括：
   - 镜头能量与目标**情绪曲线**（建置 / 发展 / 转折 / 高潮）的偏差；
   - 组间**穿插频率**（期望连续段长度由参数决定）；
   - 视觉**衔接**：正值偏顺接，负值偏跳切；
   - **源顺序保持**。
3. 按节奏曲线分配镜头长度，高潮段更碎，再迭代收敛到**目标时长**。分组方式：素材有线索归属时按线索分组，否则按视觉 k-means 聚类。

### 5. 结构诊断
诊断面板显示剧本覆盖率、平均镜头长、线索切换次数、能量贴合度（目标强度与实际能量的相关系数）、各线占比（成片与剧本对比），以及每条伏笔链的状态：完整 / 断链 / 顺序颠倒 / 无素材。

## 人工干预（导演说了算）
- **素材库**：给素材手动指定线索；填写内容描述或提示词。
- **镜头池**：逐个镜头指定线索、**锁定到某个剧本段落**或**排除**。求解器会遵守这些约束。
- **时间轴**：手动编辑之后，参数改动不会覆盖手动结果；点“生成剪辑”才会重新求解。

## 工程文件
“保存工程”会存下剧本、参数、约束、素材特征和时间轴，**不包含视频文件本身**。重新打开工程后，用“导入素材”选择同名视频即可自动关联，无需重新分析。

## 镜头语言层（导演的空间思维 × 剪辑师的非线性思维）
两个工作台共用 `js/core/grammar.js`，依据景别、角度、镜头运动三张图和 Fight Beat 分镜表的工作思路：

- **词汇**：景别（建立 / 远 / 全 / 中 / 特写 / 极特写）、角度（平视 / 高 / 俯拍 / 鸟瞰 / 低 / 虫视 / 倾斜 / 过肩 / 主观）、运动（固定 / 摇 / 俯仰 / 推 / 拉 / 跟拍 / 变焦 / 急速变焦 / 变焦滑轨 / 升降 / 航拍 / 稳定器 / 手持），以及画面方向（→ ← ↑ ↓，⊙ 表示逼近镜头）。
- **自动标注**（换角预览台追踪之后，纯算法完成）：
  - 景别看主体遮罩占画面的面积比例；
  - 镜头运动看逐帧全局位移的截尾均值，摇和跟拍再按主体是否被跟住来区分；
  - 手持看位移的抖动程度；
  - 主体方向看“画面内位移 + 镜头带走的位移”。

  在 4 个真实打戏镜头上，运动判断与人工标注一致。推和拉需要判断背景是否在缩放，目前交给手动标注或文字标签。
- **文字标签**：文件名、提示词、剧本描述里出现的“特写 / 推近 / 跟拍 / 低角度 / Wide - Track Right”等中英术语，会自动解析。
- **剪辑语法**：
  - 同一主体、同景别、同角度的两镜相接，判为跳切；
  - 同一人物左右方向反转，可能越轴；
  - 景别跨 3 级以上，算硬跳；
  - 方向一致的相邻镜头，算动作连贯，给奖励。
- **导演工作台**：
  - 线性模式新增“景别 / 运动 ↔ 剧本”匹配权重，剧本写“特写”的段落优先用特写镜头；
  - 非线性模式新增“镜头语法”和“景别随情绪推近”两项权重：高潮用近景，建置用远景，避免跳切和越轴；
  - 结构诊断里列出语法问题，点击可跳转；
  - 镜头池里可以逐镜改景别、角度、运动、方向；
  - 同名 `.json` 里的 `lang` 字段会作为该素材的镜头语言标注。
- **分镜板**：两个工作台都能导出 PNG。线稿风参照 Fight Beat：编号、`WIDE – TRACK RIGHT →` 式标题、主体运动箭头、推拉镜头的四角箭头、IMPACT 爆点；实拍帧风格则在去色的实拍帧上叠加同样的标记。

## 换角预览台（recast.html）
直接针对原片替换人物与场景，**不需要 RunningHub，也不需要任何云服务**。

1. **打开原片**：整片自动分镜。先 6fps 粗扫，再二分到单帧精度。判断切点同时用色彩直方图和 8×6 构图结构，统一调色的打戏也能切准。也可以导入旧版的 `shots.json` 或 `director_job.json`，原来的点选、描述、卡司、参考图都会接上。
2. **框选 A / B**：在任意帧拖一个框，即为该角色的关键帧。在易混淆的背景上点**负点**。
3. **追踪**（`T`）：
   - 追踪器是 CAMShift，颜色模型用前景与环带背景的后验；
   - 有遮挡判断和惯性外推，丢失后用颜色分布相似度在全画面重新检测，并补偿镜头运动；
   - 遮罩做了填洞。人物与背景同色时（如浅色衣服对浅色墙），会自动加运动约束，也可以手动开关；
   - 固定机位会生成干净背景板，做背景减除。背景板残差过大时（例如其实是慢摇），自动弃用。
4. **替换方式**（全局设置，单镜可覆盖）：
   - **换装调色**：只改演员衣着的色彩与明暗分布，原表演的每一帧动作都保留，最适合预演；
   - **贴图替身**：把新角色参考图（自动抠像）按追踪框贴上，用来检查站位、比例和色调；固定机位会先用背景板擦掉原演员；
   - **仅追踪**：只输出给本地生成用的数据。
5. **场景替换 / 整体调色**：人物遮罩之外换成新场景图，运动镜头按估计的镜头平移移动背景。
6. **导出**：
   - 整片替换预演 `.webm`：浏览器内实时合成，含原声；
   - 分镜板；
   - 镜头表；
   - **本地 ComfyUI 任务包**（可选）。

### 用本地 ComfyUI 出成片（可选，取代 RunningHub）
想把演员真正换成另一个人，仍然需要生成模型（例如 Wan2.2-Animate）。这一步改为调用你自己电脑上的 ComfyUI：

```bash
python tools/recast_local.py recast_job.json 原片.mp4            # 生成并拼回原片 → 原片_替换版.mp4
python tools/recast_local.py recast_job.json 原片.mp4 --mock     # 不调模型，先验证切片与拼接
python tools/recast_local.py recast_job.json 原片.mp4 --only S009,S044
```

脚本按时间码从原片帧精确切出每个镜头，提交到本地 ComfyUI，把生成结果统一到原片的分辨率和帧率，再按原帧位置拼回，并保留完整原声。实测未替换的镜头与原片逐帧一致（只有重编码误差），替换段的起止帧与切点完全对齐。

### 已知局限
- 颜色追踪对“固定机位或慢速运动 + 衣着与背景有色差”的镜头最可靠。快速手持、深色衣服对深色背景时容易漂移，需要在漂移开始处补一个关键帧（置信度条上会标红）。
- 重度统一调色下，浅色衣服与浅色墙几乎没有色差。即使加了运动约束，脚边地面仍可能少量渗色，这时可改用贴图替身，或多点几个负点。
- 换装调色改的是颜色与明暗分布，不改轮廓和脸。改轮廓和脸需要用上面的本地生成。

## 桌面版路线
`js/core/*` 不依赖 DOM，可以原样放进 Electron 或 Tauri。桌面版只需把 `analyzer.js` 换成 ffmpeg 解码（`-vf scale=64:-1` 输出原始帧，`-ac 1 -ar 16000` 输出 PCM），下游的切分、匹配、编排、导出代码不用改。之后可以按这个顺序补：直接调用 ffmpeg 出片、代理文件、更多导出格式（Premiere XML / OTIO）。
